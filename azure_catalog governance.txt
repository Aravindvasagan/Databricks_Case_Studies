🔥 2. What is RBAC?
👉 RBAC = Role Based Access Control
Controls: Who can access what
🔹 Azure RBAC Example
Role	Permission
Storage Blob Data Contributor	Read/write ADLS
Reader	Read only
Owner	Full access
🔥 Example
Give ADLS access to: finance_team
using Azure RBAC.
----
🔥 3. What is Managed Identity?
👉 Managed Identity = Azure-created secure identity for services
Instead of: ❌ username/password
Azure automatically creates identity.
🔹 Example
Databricks accesses ADLS using: Managed Identity
No secrets needed.
🔥 Why Needed? Secure service-to-service authentication.

🔥 4. What is Storage Credential in Unity Catalog?
👉 Storage Credential = Unity Catalog authentication object
Used to securely connect: Databricks → ADLS -> Machine-to-machine authentication
🔹 Uses
Can use: 1.Managed identity ,2.Service principal

Quick ComparisonFeature-> Service Principal | Managed Identity
What is it?	An application registration in Azure AD.A "wrapper" around a Service Principal managed by Azure. eg: Client ID & Client Secret||
Credential Management You must manage secrets/certificates manually. || Azure handles rotation and management automatically. eg: None (Handled by Azure)
Scope: 		Can be used anywhere (on-prem, other clouds). || Tied specifically to Azure resources (e.g., a VM or Function).
Best For: 	External apps or automated scripts/pipelines. || Internal communication between Azure services.
| Feature             | Managed Identity | Service Principal |
| ------------------- | ---------------- | ----------------- |
| Secret management   | Azure handles    | User handles      |
| Credential rotation | Automatic        | Manual            |
| Security            | Higher           | Medium            |
| Azure resource only | Mostly yes       | Works everywhere in (on-prem, other clouds)
| Setup complexity    | Easy             | Moderate          |
| Cross-tenant        | Limited          | Excellent         |

🔥 Important Difference Secret Scope vs Storage Credential  
| Feature                 | Secret Scope  | Storage Credential            |
| ----------------------- | ------------- | ----------------------------- |
| Used in notebook code   | Yes           | Usually No                    |
| Central governance      | Limited       | Full UC governance            |
| Best for                | App secrets   | Enterprise storage governance |
| Managed by              | Notebook/user | Unity Catalog                 |
| Fine-grained governance | Limited       | Strong                        |

🔥 When Secret Scope STILL Used?
| Scenario            | Use        |
| ------------------- | ---------- |
| API keys            | Yes        |
| JDBC passwords      | Yes        |
| Third-party systems | Yes        |
| Legacy ADLS mounts  | Yes        |
| UC storage auth     | Usually No |
🔥 Interview-Level Final Understanding
👉 Secret Scope: Securely stores secrets for notebooks/apps
👉 Storage Credential:UC-managed secure storage authentication object

Both may use same Service Principal,
BUT at different architecture layers.

🔥 One-line Interview Answer👉
dbutils.secrets and Azure Key Vault are typically used for notebook-level secret retrieval and Spark authentication, whereas Unity Catalog storage credentials centrally manage secure ADLS authentication using service principals or managed identities without exposing secrets inside notebooks.
